## Route groups

Parentheses group routes without affecting URLs. Each group's `layout.tsx` carries its own
access check, so authorization is a property of the group rather than something each page
remembers.

`src/proxy.ts` is a coarse edge gate over five prefixes. The real check is always in the
layout. `/recruitment` is the clearest case: the proxy only requires *some* session, and
the layout does the per-cycle capability check.

## Colocation

Inside a route segment:

| Folder | Holds |
|---|---|
| `_components/` | Components used only by this segment |
| `_hooks/` | Hooks used only by this segment |
| `_lib/` | Helpers used only by this segment |
| `actions.ts` | Server actions for this segment |

The leading underscore keeps a folder out of routing. There are 26 files with
`"use server"`, almost all colocated this way.

## Where a new file goes

- **Used by one route?** In that route's `_components/`.
- **Used by two routes in the same group?** The group's own `_components/`.
- **Used across groups?** `src/components/`.
- **Domain logic with no JSX?** `src/lib/`.
- **A zod schema?** `src/lib/schemas/`.
- **User-visible text?** `src/content/strings.ts`. Always.

Do not create a shared abstraction for a single caller. The convention here is to leave code
beside its only user until a second one exists.

## Path alias

`@/*` maps to `src/*`. Use it; relative parent traversal is not the house style.

## Not in the tree

`docs/` at the repository root is internal engineering material: the spec, the plan of
action, CI notes and the maintainer guide. It is excluded from `tsconfig`. This
documentation site is separate and lives under `src/app/(docs)/`.

Resend for delivery, React Email for templates, `EmailLog` for accountability.

## Sending

`src/lib/resend.ts`. The client is created lazily, so a missing `AUTH_RESEND_KEY` fails when
mail is sent rather than at boot.

`FROM` is `EMAIL_FROM`, defaulting to `noreply@deltechmun.in`.

## Every send is logged

An `EmailLog` row is written for both outcomes, with the error text on failure. That row is
what powers:

- the failed-email card on the admin overview;
- the email history in the delegate drawer;
- `resendByLogId`, the resend action;
- the idempotency check that stops selection emails double-sending.

## Failures never fail the action

Registration, allotment and selection all continue when mail fails. The row records it and a
human can resend. This is stated in [server actions](/docs/developers/server-actions) as a
general rule; email is where it matters most.

## The templates

Thirteen files in `src/emails/`, sharing `_shell.tsx`:

`registration-received`, `co-delegate-registered`, `allotment`, `co-delegate-notice`,
`payment-confirmed`, `payment-reminder`, `blog-approved`, `blog-changes-requested`,
`blog-rejected`, `recruitment-selected`, `staff-invite`, `magic-link`.

They are React components. Put shared chrome in `_shell.tsx`, not in each template.

## The staging sink

Set `EMAIL_REDIRECT_TO` and every message goes to that address instead, with the subject
prefixed to show the intended recipient:

```
[STAGING -> real@address] Your allotment
```

Set it on every non-production environment. It is the only thing standing between a staging
test and emailing real delegates.

## Magic links go through here too

The Resend auth provider supplies a custom `sendVerificationRequest` so sign-in links are
logged like everything else, rather than being invisible.

## Adding a template

<Steps>
1. Create the component in `src/emails/`, using `_shell.tsx`.

2. Put the subject in `src/content/strings.ts` under `email.subject`.

3. Send it through the helper in `src/lib/resend.ts` so it is logged.

4. Run `npm run check`. `check-emails.ts` asserts the template set.
</Steps>

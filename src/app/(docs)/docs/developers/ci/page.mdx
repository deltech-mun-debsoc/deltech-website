One workflow, one deploy path.

## The workflow

`.github/workflows/check.yml`. Triggers on **pull request** and manual dispatch. There is no
push-to-main job.

```
ubuntu-latest, Node 20
npm ci            (postinstall runs prisma generate)
npm run check     (32 assertion scripts plus the strings gate)
npm run build     (this is also the type check)
```

Concurrency group `ci-${{ github.ref }}` with cancel-in-progress, so pushing again cancels the
previous run.

`DATABASE_URL` and `DIRECT_URL` are dummy values. **The build never connects to a database**,
which is only possible because `prisma.config.ts` reads its URL through `process.env` rather
than Prisma's `env()`.

There is no separate lint or `tsc` step. The Next build does the type checking.

## Deployment

`vercel.json`:

```json
{
  "buildCommand": "npm run build:vercel",
  "ignoreCommand": "[ \"$VERCEL_GIT_COMMIT_REF\" != \"main\" ]",
  "regions": ["syd1"],
  "crons": [ ... ]
}
```

**Only `main` deploys.** The ignore command stops every other branch building, so a pull
request gets CI but not a deployment.

Functions run in `syd1`. Cron schedules are declared here; see
[cron jobs](/docs/developers/cron).

## Migrations are not automatic

The build does not run `db:deploy`. Applying a migration to production is a deliberate,
separate step. A pull request that adds a migration needs someone to apply it, and the code
must tolerate both schema versions during the window between deploy and migrate, or the
migration must go first.

## Environments

| Environment | Notes |
|---|---|
| Production | `deltechmun.in`, plus `docs.deltechmun.in` for this site |
| Preview | `test.deltechmun.in`. The admin header shows a preview badge. |
| Local | `localhost:3000` |

Set `EMAIL_REDIRECT_TO` on every non-production environment.

## The docs subdomain

`docs.deltechmun.in` is the same Vercel project. A host-matched `beforeFiles` rewrite in
`next.config.ts` maps it onto `/docs`. Adding the domain in the Vercel dashboard is a manual
step outside the repository.

## Before opening a pull request

```bash
npm run check && npm run build
```

Both are exactly what CI runs. See [contributing](/docs/developers/contributing).
